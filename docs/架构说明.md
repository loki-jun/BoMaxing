# BoMaxing 核心架构

## 当前目标

先建立与 UI、相机 SDK 和具体通信协议无关的运行时内核，让平台具备：

1. 工程定义；
2. 流程连接；
3. 工具注册；
4. 拓扑排序；
5. 工具执行；
6. 结果和诊断；
7. 工程保存与加载。

后续所有 2D、3D、AI、设备和通信能力都通过工具或插件接入，不直接修改流程执行器。

当前已经打通第一条 2D 链路：

```text
PGM 文件 / 外部 Image2D
        │
        ▼
Gray Threshold
        │
        ▼
Region Measure
        │
        ▼
Measurement
```

## 工具执行契约

工具只关心三类输入：

- `Inputs`：来自上游节点或外部触发的数据；
- `Parameters`：工程中保存的配置参数；
- `CancellationToken`：用于停止、超时和关机。

工具输出统一为 `ToolExecutionResult`：

- `Succeeded`：是否执行成功；
- `Outputs`：按端口命名的数据；
- `Diagnostics`：工具级诊断信息。

## 数据类型策略

`DataValue` 已经预留了 2D/3D 所需的数据类型：

- `Image2D`
- `DepthMap`
- `PointCloud`
- `Region2D`
- `Geometry`
- `Pose`
- `Measurement`
- `Record`

`Image2D` 支持 Gray8、Gray16 和 Float32 采样，并同时提供原始采样访问和 8 位显示视图；现有 Gray8 工具继续读取显示视图以保持兼容。`Region2D` 为与图像同尺寸的二值掩膜。核心层已提供通用 `PooledMemoryLease<T>`，以引用计数方式管理可复用的大型临时缓冲；后续相机帧、深度图和点云适配器应通过该租约接入零拷贝路径。

## 通信与设备边界

通信层统一为 `IByteChannel`：

- `TcpClientChannel`：TCP 客户端连接、发送、接收、精确长度读取和状态事件；
- `ModbusTcpClient`：保持寄存器读取、单寄存器写入和 Modbus 异常码；
- `SerialPortChannelAdapter`：通过流适配器承载串口实现，核心层不绑定具体串口 SDK；
- `CommunicationChannelRegistry`：按工程级 ID 管理连接资源。

设备层统一为 `IDevicePlugin` 和 `IDeviceSession`；可配置设备额外实现 `IDeviceFeatureSession`，提供参数读取和写入。GenICam 相机、厂商 3D 相机、光源和 IO 都通过插件注册，不直接进入流程引擎。工业协议 session 可包裹统一的重试、退避和断线重连策略。

## 跨平台和原生 SDK 策略

核心运行时目标为 `.NET 8`，不引用 WPF、Qt 或厂商 SDK。未来 Studio 优先采用 Avalonia，以支持 Windows 和 Linux。

3D 相机 SDK 通过两层边界接入：

1. C# `ICameraSession`：定义连接、能力声明和采集结果；
2. C ABI `bomaxing_device_api.h`：供 C++ 厂商适配层和驱动宿主使用。

默认使用进程外驱动：

```text
BoMaxing Runtime (.NET)
        │ IPC / shared memory
        ▼
Native Driver Host (C/C++)
        │ vendor SDK
        ▼
3D Camera
```

这样厂商 SDK 崩溃、运行库冲突和平台差异不会直接拖垮主流程。只有在实测采集节拍证明 IPC/复制成为瓶颈时，才允许签名的进程内插件。

统一帧模型包括 `ImageFrame`、`DepthMap` 和 `PointCloud3D`，每个结果都携带设备 ID、序号、时间戳、像素格式、单位比例和坐标系。

## 流程执行规则

- 节点通过边连接，边表达端口间的数据依赖；
- 执行前检查节点 ID、工具类型、边引用和循环；
- 使用拓扑顺序执行；
- 默认遇到工具失败立即停止；
- 每个节点记录耗时、输出和诊断；
- 外部输入使用 `节点ID.端口名` 作为键传入。

## 已完成的阶段能力

- 工程 schema v1 到 v2 迁移，新增描述和工程设置字段；
- ROI 裁剪、均值滤波、形态学膨胀/腐蚀、连通域分析；
- 深度图阈值、点云 Z 过滤和点云包围盒测量；
- 通信发送和定长接收工具，使用 Runtime 注入的通道注册表；
- 节点超时、取消和独立分支并行执行；
- Avalonia Studio 外壳、真实 Demo 流程执行反馈和运行日志；
- 原生驱动宿主的 ABI 检查、版本化二进制 IPC 和共享帧池契约；
- 设备采集工具、工业协议契约、权限认证和部署包清单。
- Studio 现场状态摘要、设备操作权限、部署包校验、版本目录切换和回滚。
- `BoMaxing.Service` 常驻宿主、Windows/systemd 服务文件生成和部署后一次性健康检查。
- Studio 运行历史独立文件持久化、最近运行恢复和耗时趋势摘要。
- 运行历史查询服务支持时间范围、工作流、状态筛选、分页和时间桶聚合。
- HMI 工程模型支持 Text、Number、Boolean、Status、AlarmList、Trend、Image 组件；Studio 已支持受约束数据点目录、组件类型兼容校验、运行态解析、标题、刷新周期和增删编辑。
- 大数据缓冲区提供对象池租约和引用计数测试，后续设备适配器可在不改变流程契约的情况下接入。
- Studio 已提供独立 HMI 运行窗口，复用同一套数据点解析和运行态状态。
- C++ 驱动宿主二进制 IPC 模式、共享帧池发布和 C# `protocol=binary` 适配选择。

## 后续产品化工作

1. 在目标 Windows/Linux 工具链编译验证 C++ 宿主，并接入具体 3D 相机 SDK；

3. 扩展 TIFF 私有 codec、Tile TIFF、复杂多平面格式，并实现大对象池化；
4. 为现场项目制作 Windows/Linux 安装器、服务注册和升级回滚验证流程；
5. 将 HMI 数据点目录继续扩展到设备/通信变量，并制作独立 HMI 运行端和现场画面模板。
