# BoMaxing 开发计划

## 已完成

- .NET 8 核心运行时、工程模型、JSON 保存加载和 schema v1/v2/v3/v4 迁移。
- 拓扑执行、循环检查、失败停止、取消、节点超时、独立分支并行和回放上下文。
- Gray8/Gray16/Float32 图像、二值区域、测量、深度图、点云和统一预览摘要模型。
- PGM、BMP、PNG、TIFF 图像源；支持常用 TIFF 压缩、RGB 转灰度和大端数据；ROI 裁剪、均值滤波、阈值、形态学、连通域、深度阈值、点云过滤和包围盒测量。
- TCP、Modbus TCP、串口通道抽象，Modbus 读写、协议帧模板、通信发送/定长接收工具和工业协议重试策略。
- OPC UA/PLC/机器人统一变量、命令契约、注册表和流程工具。
- 设备插件、设备会话管理器、Camera Capture 工具、录制相机回放、GenICam 适配契约、原生 C ABI、进程外驱动宿主客户端和 Demo Camera 插件。
- Avalonia Studio 工程导航、动态流程节点、工具箱添加节点、工程节点位置、动态连线、节点拖拽、节点选择、参数 Schema、保存/加载、运行/停止和日志。
- 执行前端口类型和参数校验，运行快照保存/加载。
- 工程 schema v4、配方持久化、报警确认/清除、审计记录、角色权限和部署包清单/哈希校验。
- 原生版本化 IPC 和共享帧池。
- 大图像、深度图和点云可复用的通用对象池租约，支持引用计数和最后租约归还。
- 71 项核心测试和可运行的控制台 Demo。
- HMI 工程配置、Studio 组件编辑、运行历史筛选/分页/趋势聚合。

## 当前产品化边界

- TIFF 常用压缩和高位深核心读取已经完成；厂商私有 TIFF codec、Tile TIFF、复杂多平面格式、GenICam 厂商 transport、OPC UA/PLC/机器人现场适配和具体厂商 SDK 仍需要独立适配器或第三方 SDK。
- C++ 驱动宿主已提供 `--ipc` 二进制协议模式、跨平台共享帧池发布和 CRC32 校验；当前环境缺少 CMake/C++ 编译器，仍需在目标 Windows/Linux 工具链做编译与厂商 SDK 验证。
- Studio 当前已具备现场 HMI 状态摘要、登录/退出、设备在线连接/采集/特性参数读写和操作权限控制；部署运行时已具备包校验、release 切换、回滚、Service 宿主和服务文件生成，目标系统服务注册仍需由现场安装流程执行。

## 当前阶段收口

- Studio 已增加运行历史独立持久化、启动恢复、成功率/平均耗时、筛选/分页/趋势摘要，以及可持久化 HMI 组件编辑；HMI 已采用受约束的数据点目录，支持运行态值解析、组件类型校验、报警列表、图像、趋势和空值状态。
- 部署运行时已增加安装后健康检查、旧 release 清理和 Service `--health` / `--prune` 入口；Windows/Linux 安装器和服务注册仍应在目标系统按运维规范制作和验证。
- C++ 驱动宿主已接入二进制 IPC、共享帧池发布和 CRC32；当前环境没有 CMake/C++ 编译器，必须在目标工具链编译验证后才能进入生产 SDK 集成。
- OPC UA、PLC、机器人和海康/康耐视/天云等厂商适配仍需要明确设备型号、SDK 版本和现场协议，当前保持通用契约与模拟测试，不伪造真实设备集成。

## 下一阶段

1. 在 Windows/Linux 目标工具链编译并运行 C++ 驱动宿主，接入第一款真实 3D 相机 SDK。
2. 选定一套真实 PLC/机器人协议，完成连接、变量读写、命令确认、异常码和断线恢复的现场测试。
3. 将 HMI 数据点目录继续扩展到真实工艺、设备和通信变量，并补充现场画面模板、组件专用渲染和独立部署运行端。
4. 将对象池租约接入相机帧、深度图和点云的零拷贝适配路径，减少流程节点间的大对象复制。
5. 为目标客户制作安装器、服务注册、升级回滚和现场诊断包。
